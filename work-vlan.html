Network Segmentation Across a Three-Site Compound

Three main locations — A, B, and C — kilometers apart inside one big compound, all shouting on a single flat network. Broadcasts everywhere, stability nowhere. Fixed together with my Senior IT Engineer.

The situation

A large compound with three main locations, A, B, and C, kilometers apart. Each location is self-contained: main office, staff accommodation, warehouse, and a working factory with its machinery — plus Wi-Fi access points, cameras, and printers. All of it sat on one flat network. Broadcast traffic and congestion made the whole thing unstable: a problem in one location was everybody's problem.

We took this on together: split the compound into isolated segments so each location stands on its own — without breaking the locations still running on the old network during the rollout. Lab tested first, because a live compound does not forgive guesswork.

Segments are fully isolated — no traffic between VLANs. Each location is its own broadcast and collision domain, enforced by FortiGate policies and per-location L3 switching.

Hardware Used

  • FortiGate Next-Generation Firewall — security policies configured
  • L3 switches — one main switch per location (VLANs, dedicated ports)
  • Fiber backbone between locations + splicing and fiber-to-ethernet media converters at endpoints — pre-existing, left unchanged
  • Segregated cabling per location + re-labelled patch panels
  • Wireless access points per location, printers and machinery on static IPs

What we actually did

Lab first (2 days): we designed the segmentation, built it on a lab setup, planned the cutover order, and tested routing, policies, and failover behavior before touching anything live. Location A: we deployed VLAN 20 — configured the L3 switch, FortiGate routing and policies, access points, and static IPs for printers and machinery — then watched it for a full day for faults and load issues while Locations B and C stayed on the previous network, unaffected. Location B: same cutover to VLAN 30, another day of watching for errors and load. Location C: same cutover to VLAN 40. After the last watch period with zero issues, all three locations were on segmented, isolated networks. The fiber plant and media converters were never touched — only the firewall side and the new L3 switches changed.

Results

  • Broadcast congestion gone — each location is its own quiet domain.
  • A fault in one location stays in that location instead of taking down the compound.
  • Stable, secure, and fast: granular traffic control plus no cross-segment lateral movement.
  • Documentation: one-page VLAN + IP sheet per location. Future-me says thanks.
